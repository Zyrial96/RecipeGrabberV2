## Exact Production Installation And Recovery

- MIUI rejected fresh USB installation with INSTALL_FAILED_USER_RESTRICTED.
  The exact signed APK was instead opened in Files and installed through the
  normal package installer. Play Protect scanned it and reported it apparently
  safe; Xiaomi's scan also passed. No protection was disabled or bypassed.
- The installed APK was read back from the device and matched the production
  SHA-256 above. Package metadata reports 2.1.0/code 2, with no DEBUGGABLE flag.
- Drive authorization succeeded using the existing release-certificate client.
  No new OAuth client, scope, IAM, billing or consent-publication change was
  needed. The first library was empty, visibly reporting zero recipes.
- The latest preflight snapshot, `2026-10-23T21:15:34.324Z`, listed four recipes.
  Its first restore reported `Restored 4 recipes; 0 existing recipes kept`.
  Repeating it reported `Restored 0 recipes; 4 existing recipes kept`.
- After force-stop/relaunch the library still showed exactly four recipes.
  All four independent detail views opened, including the two distinct tortilla
  records. The newly extracted six-step recipe and both tortilla sequences
  (eight and seven steps) were scrolled through to their final steps.
- On the newly extracted recipe, two to three portions scaled four eggs to six
  and one unit of butter to 1.5. Returning to two restored the displayed amounts.
- Its Originalvideo ansehen button resumed the installed YouTube watch activity
  with the exact saved HTTPS URL and BROWSABLE intent. A fresh UI tree showed
  the cooking video's paused player. No advertisement was selected.
- Fresh screenshots of the actual release library in light/dark themes and its
  source-button detail view were visually inspected. Artwork, controls and text
  rendered without incoherent overlap. Dark mode was restored afterward.
- Gemini Google OAuth was reconnected in Settings. This is authorization
  evidence, not a new live generation/upload test. No optional upload permission
  or Apify credential was added.
- The production app created a new four-recipe Drive snapshot at
  `2026-10-23T21:25:46.391Z`, which appeared alongside the retained snapshots.

## Retained State And Limits

The actual signed production app remains installed on the Mi 11 with all four
restored recipes. Private raw backups, rollback APK and screenshots remain
outside Git, as do all signing material and account data. No cloud snapshot was
deleted, and the S25 was not modified.

This was an explicitly authorized fresh installation after backup, not an
in-place debug-to-release upgrade. Fresh-install database IDs can differ; no
raw post-release database equality is claimed because release is non-debuggable.
The preflight probe verified exact backup contents; post-release evidence is
the real cloud restore, UI readback and restart. No new inference, Play-store
publication, Android system-backup recovery, broad animation/performance audit
or new-device test was performed in this release run. Off-device signing-key
backup and same-certificate older-version update acceptance remain separate.
